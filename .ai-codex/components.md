# Component Index — SecVault

Dense lookup table of every React component under `components/**`. `(c)` prefix = client component
(`'use client'`). No prefix = server component. Format: `(c) Name  prop1, prop2 — purpose`.
Generated by reading every file directly; not hand-maintained prose — re-generate if this drifts.

(c) AcknowledgeButton  deviceId, diffId — acknowledges a config diff, optional note
(c) ConditionsManager  cveId, initialConditions, devices, canWrite — CRUD + test UI for advisory applicability conditions; list renders each predicate config as compact key=value chips (ConfigChips), not a raw JSON <pre> block
(c) DiffViewer  deviceId, diffId — expandable rule-change/section view of a config diff. Rule Changes (2.33.0) is a COLLAPSED-by-default accordion (RuleChangeCard) with Expand/Collapse all — one line per rule (name + change badge + ellipsis summary); expanding shows the whole rule as a ManageEngine-style horizontal rule table (RuleSnapshotTable, 2.51.0 — replaced RuleDetailGrid, which replaced the tall 12-row RuleDetailTable) or a field-change grid (RuleFieldChangeList). Also: per-section groups, flat-object/diff tables, and (2.29.0) per-rule tables for Palo Alto XML/API "Security Rules" entries regrouped by ruleIndex ("Rule #N", or the real @_name on a whole-rule add/remove) — 2.51.2 replaced that group's Field|Change|Value table: splitRuleGroupEntries() hoists whole-rule entries into a FULL-WIDTH RuleSnapshotTable (a modified rule contributes two rows, Old Details + New Details, in ONE table) while per-field edits render as IndexedFieldChange pill+value cards, and the change type moves to a pill in the group header. Nesting the rule table in a VALUE cell had left all 11 rule columns truncated ("RULE…", "SRC …"). Nested object/array values render as nested TABLES (ValueTable, 2.51.0 — supersedes ValueTree, which is kept only as the past-MAX_TABLE_DEPTH fallback): an object becomes a Field|Value table, an ARRAY OF OBJECTS becomes one table with a column per union key (ObjectArrayTable, capped at MAX_OBJECT_TABLE_COLUMNS=8), arrays of primitives comma-join. PAN-OS `{member:[...]}` list wrappers are unwrapped (unwrapMember) and the fast-xml-parser `@_` attribute prefix is stripped from labels (stripAttrPrefix; titleCaseField also maps acronyms via FIELD_ACRONYMS). ⛔ A WHOLE-rule add/remove on the XML/API path is normalized through the adapter's own `parser.parseRuleEntry` (tryBuildRuleFromXmlValue) and rendered as RuleSnapshotTable — before 2.51.0 it fell through isFlatObject() and dumped the raw nested structure, the worst rendering in the view. Every table sits in its own `overflow-x:auto` box so a wide rule scrolls in-card rather than clipping; each section list caps at SECTION_ROW_LIMIT rows with a "Show all (N)" toggle (tames historical 200+-row membership cascades)
